# Мои решения · API v1

Бот и мини-приложение читают список действий от имени участника. Ядро определяет участника и профиль по индивидуальной учётной записи. В браузере путь начинается с `/tracker/api/`, в ядре с `/v1/`. Ответы имеют `Cache-Control: no-store`.

| Метод и ресурс | Результат |
|---|---|
| GET priorities | 200 ready со списком в порядке показа. Пустой массив означает, что сейчас от участника не требуется действий. 202 pending означает, что идёт обновление. Клиент скрывает предыдущий список. |
| GET priorities/{action_id} | 200 с актуальной карточкой действия. Временное обновление возвращает 202. Если действие завершено или утратило видимость, возвращается 404. Штатную карточку поручения открывают по `step_id`. |
| GET и POST priority-preferences | Часовой пояс, фокус проекта, локальный день окончания фокуса включительно (focus_until) и горизонт близкого срока. Первая версия 1. POST принимает `expected_version` и изменяемые поля. |
| GET и POST tasks/{step_id}/priority-facts | GET возвращает действующие факты и версию для проверяющего. Поле can_manage_priority_facts на карточке поручения разрешает редактирование.  Проверяющий подтверждает факт на `expected_version` шага. Можно, например, задать `waiting_for_response` и `expected_response_at`, либо передать `response_confirmed: true` при получении ответа. Команда возвращает карточку поручения с новой версией. |
| GET и POST priority-settings | Настройки теневого журнала. По умолчанию version 0 и enabled false. POST propose сохраняет проект, confirm применяет показанную версию, revoke отключает журнал и удаляет его прогнозы и наблюдения. Для каждого изменения нужен expected_version. |
| POST priority-feedback | При feedback_enabled=true передать list_id, action_id, expected_version действия и choice (choose, defer, correct). Допускается короткая причина reason. 200 recorded означает, что выбор учтён. 409 требует обновления списка, 404 означает исчезнувшее действие, 403 означает отсутствие согласия или доступа. |

Для записей клиент задаёт заголовок `Idempotency-Key`. Повтор той же попытки использует тот же ключ и тело. Профиль и адресат в теле запроса не расширяют полномочия. Неподтверждённая сессия получает 401.

## Поля выдачи

В готовой очереди `list_id` идентифицирует показанный набор, `position` — обработанную позицию профиля, `computed_at` — время расчёта, `profile_version` и `policy_version` — версии настроек базовой очереди и правила. Флаг `feedback_enabled` означает, что по сохранённому прогнозу можно оставить выбор. После первого принятого выбора флаг выключается для этого показа. Прогноз не меняет видимого порядка.

Действие содержит `action_id`, `step_id`, `title`, `next_actor_id`, `kind`, `tier` (0 первым), `reason_code`, `reason_text`, `source_ref`, `due_at`, `expected_response_at`, `check_at` и `version`. День без времени остаётся датой, момент содержит смещение часового пояса, неизвестная дата передаётся как null. Один шаг может одновременно требовать решения и проверки ответа.

## Личный календарь и история

GET priority-calendar возвращает текущий снимок свободного времени. POST принимает expected_version (первый снимок — 0), coverage_start, coverage_end и free_intervals — массив пар моментов со смещением. Владелец подтверждает полноту календаря на всём заданном периоде. Пустой массив внутри покрытия означает занятость. За пределами покрытия запас неизвестен. Пересекающиеся интервалы объединяются. Потребность округляется вверх, доступные целые 15-минутные блоки — вниз внутри каждого непрерывного интервала. Для неделимой работы учитывается возможность целиком поместиться в одно окно.

GET tasks/{step_id}/priority-history возвращает доступную историю версий и оснований. Чтение повторно проверяет права на шаг.
