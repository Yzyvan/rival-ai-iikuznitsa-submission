# Миниапп Vilar

## Запуск и проверка

Команды для каталога `prod/miniapp`

```sh
npm ci
npm run dev
```

Vite поднимает интерфейс на `http://127.0.0.1:5173`. Без данных входа он показывает демонстрационный сценарий. Для экранов аккаунта нужны серверные API и авторизованный запуск. Команда `npm run build` проверяет типы TypeScript и собирает приложение в `dist/`. Команда `npm run preview` открывает собранный интерфейс локально.

Проверки профиля и карточек запускаются из того же каталога после сборки. Нужны Python с пакетом Playwright и установленный Chromium. Путь к существующему браузеру можно передать через `CHROMIUM_EXECUTABLE_PATH`.

```sh
python checks/outlook_profile.py
python checks/day_mail_cards.py
```

Из каталога `integrations/outlook` проверки адаптера запускаются командами `npm ci`, `npm test` и `python -m unittest test_mail_push test_vilar_graph`. Они используют тестовые сообщения и ответы провайдера.

## Поручения

На Доске откройте этап «Поручения». Просроченные поручения находятся в шапке, остальные — в разделе «В работе». Нажатие открывает карточку с исполнителем, сроком, состоянием и причиной позиции в очереди. Данные и порядок приходят из `GET /vilar-contest/api/day` в полях `queue` и `task`. Ответ исполнителя берётся из `reply.body`. При наличии `reply.task_id` карточка определяется по идентификатору. Без него ответ показывается только при одном завершённом поручении.

В фазе `approve` сервер принимает `POST /vilar-contest/api/day` с `action: "advance"` и значениями `generation`, `round`, `revision` из прочитанного состояния. Демонстрационный экран выбора исполнителя работает отдельно. Кнопка «Другой» раскрывает остальных участников демонстрационной встречи.

## Почта и протокол встречи

| Запрос | Как его использует миниапп |
|---|---|
| `GET ./api/front/v1/mail?day=YYYY-MM-DD` | Загружает дневной список. Следующая страница запрашивается с полученным `cursor`. |
| `GET ./api/front/v1/mail/{id}` | Загружает отдельный тикет, в том числе при открытии `?open=mail:{id}` вне текущего дневного списка. |
| `POST ./api/front/v1/mail/{id}/actions/{action}` | Передаёт действие, версию тикета и полезную нагрузку с заголовком `Idempotency-Key`. Карантин и подтверждение отправки используют разрешённые для карточки действия. |
| `GET ./api/mail/board` | Загружает прежний список писем, если адрес дневного списка вернул 404. |
| `GET ./api/owner/document` | По параметрам `kind=mail` или `kind=protocol` и `id` возвращает документ и его версию. Для письма `body` содержит оригинал, `text` — сохранённый черновик. |
| `POST ./api/owner/document` | Сохраняет правку черновика или протокола с полями `kind`, `id`, `text`, `version`. Конфликт версий возвращает 409. |

Сводка письма показывается первой. Полный текст раскрывается внутри карточки. Если сводки нет, оригинал виден сразу. В разделе «Vilar решил сам» входящее письмо и результат оформлены перепиской. Подпись «Vilar ответил» опирается на подтверждение отправки в тикете. Делегирование, включение в сводку и сохранённый черновик показываются отдельно от отправленного ответа.

При 404 документа доступны данные самого тикета и разрешённые для него действия. При 401 или 403 просмотр документа ограничен. Для редактирования черновика и протокола нужны права записи. Сохранение документа не отправляет письмо и не меняет время встречи.
