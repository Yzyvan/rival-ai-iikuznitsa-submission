# Подключение почты и календаря Outlook к Vilar

Мини-апп привязывает ящик Microsoft к владельцу подтверждённого Telegram-сеанса. Первый вход открывает чтение двух источников. Из профиля руководитель может разрешить запись или отключить сразу оба источника. Адаптер работает с Microsoft Graph v1.0. Существующий консольный `integrations/outlook/outlook login` использует собственный кэш и остаётся отдельным инструментом для проверки тестового ящика.

## Entra и права

Для демонстрации с Outlook.com и рабочими Microsoft 365 зарегистрировать **Web**-приложение в Entra с аудиторией *Accounts in any organizational directory and personal Microsoft accounts*, authority `common`. Указать точный HTTPS redirect URI `/auth/microsoft/callback` сайта Vilar. Для закрытого корпоративного пилота выбрать single-tenant в регистрации и GUID этого каталога в настройках сервера. Нужен ящик с доступом к Exchange Online или Outlook.com. [Регистрация приложения](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app)

| Действие | Delegated scope | Что получает Vilar |
| --- | --- | --- |
| Читать письма и цепочки | `Mail.Read` | Текст и краткое содержание. `Mail.ReadBasic` исключает эти поля. |
| Читать расписание | `Calendars.ReadBasic` | Экземпляры встреч, время, участники и занятость без вложений и описания. |
| Продолжить после закрытия мини-аппа | `offline_access` | Refresh-токен для этого владельца. |
| Разрешить черновики и изменения встреч | `Mail.ReadWrite`, `Calendars.ReadWrite` | Дополнительный интерактивный вход из профиля. Черновик ответа сохраняется в Outlook. |

Профиль Microsoft не запрашивается, поэтому `User.Read` не требуется. Отправку подтверждает сам руководитель кнопкой «Отправить» в Outlook, куда ведёт `webLink` черновика. У сервера нет операции отправки и он не запрашивает `Mail.Send`. Для будущей отправки из Vilar понадобятся отдельное согласие на `Mail.Send`, привязка решения к адресатам и точной версии черновика, исполнение через очередь и сверка результата. [Разрешения Graph](https://learn.microsoft.com/en-us/graph/permissions-reference) · [Чтение календаря](https://learn.microsoft.com/en-us/graph/api/calendar-list-calendarview) · [Создание черновика ответа](https://learn.microsoft.com/en-us/graph/api/message-createreply)

Эти delegated-разрешения допускают согласие пользователя по классификации Graph. Администратор клиента может запретить пользовательское согласие или разрешать его только проверенным издателям для выбранных прав. До пилота согласовать набор прав с IT и при необходимости получить tenant admin consent. Для многопользовательского корпоративного распространения подготовить домен издателя и publisher verification через Partner Center. [Проверка издателя](https://learn.microsoft.com/en-us/entra/identity-platform/publisher-verification-overview)

## Последовательность входа

1. Экран «Подключения» читает `GET /me/connections`. Мини-апп передаёт исходную строку Telegram в заголовке `Authorization: tma <initData>`. Сервер проверяет HMAC-SHA256, время и Telegram user ID. Срок допуска запроса — час, допустимое опережение часов — 30 секунд. После истечения открыть мини-апп заново. [Проверка initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app)
2. «Войти в Microsoft» вызывает `POST /auth/microsoft/intent` с `{"mode":"read"}`. Для записи профиль передаёт `manage`. В ответе приходит URL с одноразовым случайным билетом. Следующее нажатие открывает этот URL через `Telegram.WebApp.openLink` непосредственно из жеста пользователя. Параметр `state` не содержит Telegram ID или initData.
3. `GET /auth/microsoft/start?state=…` расходует билет, устанавливает защищённую браузерную cookie и отправляет браузер на Microsoft. Сервер генерирует новый `state` и PKCE S256. Время жизни каждого этапа — 10 минут. Повторный запрос на привязку заменяет старый.
4. `GET /auth/microsoft/callback` сверяет cookie и state, однократно обменивает code и verifier на токены. При отказе возвращает в Telegram с `startapp=ms_error`. При успехе сервер выдаёт ссылку в настроенный мини-апп с одноразовым параметром завершения. [Authorization code + PKCE](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)
5. Мини-апп вызывает `POST /auth/microsoft/finish`. Сервер берёт параметр возврата из подписанного Telegram initData и сверяет владельца с исходным. Затем мини-апп проверяет по одной записи каждого источника. Профиль показывает статусы отдельно. Во время ожидания мини-апп опрашивает только локальные статусы раз в пять секунд, пока экран видим.

## HTTP-договор

Все маршруты, кроме браузерных `start` и `callback`, требуют заголовок Telegram. Идентификатор владельца в теле запроса не принимается.

| Метод и путь | Результат или параметры |
| --- | --- |
| `GET /me/connections` | Например, `{"mail":"connected","calendar":"error","can_manage":false}`. Статус отражает последнее известное состояние. |
| `POST /me/connections/check` | Проверка обоих источников через Graph. Возвращает статусы без содержимого. |
| `DELETE /me/connections/microsoft` | Удаляет общий локальный доступ и незавершённую привязку этого владельца. |
| `GET /outlook/mail/latest` | До десяти последних входящих по времени получения, ID цепочки, отправитель, тема и фрагмент текста. |
| `GET /outlook/mail/thread?conversation_id=…` | Письма цепочки в ящике с телами. При выводе HTML-тела нужна очистка или текстовое представление. |
| `POST /outlook/mail/{id}/reply-draft` | JSON `{"text":"Текст ответа"}`. Возвращает ID и ссылку Outlook. При неясном исходе сверить папку «Черновики» перед повтором. |
| `GET /outlook/calendar/tomorrow?tz=Europe%2FMoscow` | Завтрашние сутки в IANA-поясе, все страницы календаря, участники и свободные интервалы в UTC. Границы считаются отдельно для каждой полуночи. Окна относятся к основному календарю владельца за полные сутки. |
| `POST /outlook/calendar/events` | `subject`, `start`, `end` с явным смещением, список адресов `attendees`, UUID `transaction_id`. При повторе той же операции использовать прежний UUID. Graph может отправить приглашения участникам. |
| `PATCH /outlook/calendar/events/{id}` | `start`, `end`, `etag` из поля Graph `@odata.etag`. При 412 перечитать событие и согласовать новое время. |

Режим чтения возвращает 403 для операций записи. Недействительный refresh-токен переводит оба источника в `needs_login`. Ограничение Graph возвращается как 429 с числовым `Retry-After`, когда провайдер его передал. Для Outlook Microsoft указывает 10 000 запросов за 10 минут и четыре одновременных запроса на сочетание приложения и ящика. [Лимиты Graph](https://learn.microsoft.com/en-us/graph/throttling-limits#outlook-service-limits)

## Хранение и отключение

Секрет приложения Entra, токен существующего бота и ключи шифрования поступают в процесс через менеджер секретов. Сервер хранит access- и refresh-токены, PKCE и временные результаты входа зашифрованными Fernet в SQLite. В индексах лежат хеши билетов, ID владельца и сроки. Базу и резервные копии держать вне web-root и репозитория. Ротация MultiFernet описана в инструкции сервера. При обновлении сервер сохраняет выданный Microsoft новый refresh-токен. Один процесс обслуживает базу, операции одного владельца сериализованы.

Отключение в профиле удаляет локальные токены и запрещает завершить старую попытку входа. Для полного отзыва согласия владелец также удаляет приложение в настройках Microsoft, в управляемом тенанте это может сделать администратор. Простое удаление из SQLite не аннулирует уже выданный провайдером access-токен. В эксплуатационные метрики подходят маршрут-шаблон, класс результата, HTTP-статус и задержка. Отключить запись URL с query, заголовков, cookie и тел на reverse proxy, в APM и в журнале Uvicorn. Письма и встречи в эту БД не записываются.

## Изменения после подключения

Для хакатона чтение выполняется по запросу. Если появится фоновая синхронизация, начать с delta для выбранной папки писем и `calendarView/delta` для фиксированного диапазона. Обходить все `nextLink`, сохранять непрозрачный `deltaLink` после успешного приёма всей порции. Для нового диапазона календаря начинать новый курсор. Потерянный курсор требует полной синхронизации нужного окна. [Delta писем](https://learn.microsoft.com/en-us/graph/delta-query-messages) · [Delta календаря](https://learn.microsoft.com/en-us/graph/delta-query-events)

Для пилота с короткой задержкой нужны basic change notifications на `/me/messages` и `/me/events`, публичный HTTPS webhook с возвратом validationToken, проверка clientState, быстрая постановка в очередь и дедупликация. Хранить ID и время истечения подписки, продлевать заранее и пересоздавать утраченную. Максимум для обычных Outlook-подписок — около семи суток, с содержимым — менее суток. При пропуске уведомлений восстанавливать изменения по delta. Для корпоративного пилота согласовать частоту и срок хранения. [Подписки и сроки](https://learn.microsoft.com/en-us/graph/change-notifications-overview)

## Дизайн, границы и приёмка

- Две независимые строки. Начальная загрузка, требуется вход, ожидание Microsoft, подключено, ошибка источника и повторная проверка. Профиль содержит общее действие «Отключить Microsoft» и отдельное согласие на запись.
- Согласовать с заказчиком тип тенанта, набор сотрудников, рабочий пояс и часы, допустимость приглашений, сроки хранения, отзыв и место окончательного подтверждения письма. Доступность коллег и переговорных требует отдельного сценария free/busy.
- По архитектуре Vilar письма и события должны проходить карантин до анализа и записи в основную базу. Эти маршруты читают данные для их владельца. Автоматическая передача в карантин, обработка ИИ, очередь отправки, delta и webhook относятся к следующему этапу. Остальные экраны онбординга содержат исходные демонстрационные данные.
- Telegram здесь подтверждает пользователя мини-аппа. Подключение личных чатов по MTProto в эту поставку двух интеграций Microsoft не входит.

Фронтенд собирается в `prod/miniapp` командами `npm ci` и `npm run build`. Раздавать `dist/` на том же HTTPS origin, что и маршруты сервера. Для запуска API и тестов см. [инструкцию закрытого сервера](https://github.com/Yzyvan/vilar-core-api/blob/feat/miniapp-source-auth/connections/README.md).
